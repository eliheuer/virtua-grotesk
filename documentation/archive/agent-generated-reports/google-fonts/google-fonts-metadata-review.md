# Google Fonts Metadata Review

`METADATA.pb` should be generated downstream by `gftools packager`, then reviewed
against this checklist before opening the final `google/fonts` pull request.
Resolve `documentation/google-fonts/google-fonts-decisions.md` before treating this file as
final.
Review `documentation/google-fonts/generated-font-metadata.md` before packaging to confirm
that built binary metadata matches this expected downstream metadata.
Review `documentation/source/source-ufo-metadata.md` at the same time to confirm the
active UFO source metadata matches the generated binaries.
Review `documentation/google-fonts/downstream-metadata-readiness.md` to compare this preview
against the current built variable font and to list pending source/metadata
placeholders.

The Google Fonts metadata guide says `METADATA.pb` contains library-facing
metadata and font-file metadata, can be partially generated by `gftools`, and
still needs human review.

## Expected family metadata

```text
name: "Virtua Grotesk"
designer: "Eli Heuer"
license: "OFL"
category: "SANS_SERIF"
stroke: "SANS_SERIF"
date_added: "Pending final Google Fonts date_added"
```

Open review items:

- Confirm the matching `Eli Heuer` designer profile entry or profile PR.
- Replace the pending `date_added` placeholder with the final Packager-generated
  or reviewer-approved first-add date before applying downstream metadata.
- Review `documentation/google-fonts/designer-profile-readiness.md` so every final
  `designer` value has a matching `google/fonts/catalog/designers` profile or
  a prepared profile request.
- Confirm upstream repository URL and final source commit.
- Confirm whether built fonts are committed upstream or packaged from generated artifacts.
- Confirm first-submission subsets and primary script against
  `documentation/google-fonts/gf-glyphset-readiness.md` and
  `documentation/google-fonts/google-fonts-language-metadata.md` after the PUA scope
  decision.
- Review `documentation/google-fonts/pua-scope.md` before finalizing subsets and package
  warnings if the private-use icon block remains encoded.
- Confirm whether `classifications` should be unset or include `DISPLAY`.
- Confirm `category: "SANS_SERIF"` and `stroke: "SANS_SERIF"` remain the right
  catalog classification for the final design.
- Confirm designer order and designer-profile tracking before the downstream
  PR, matching the checklist used in recent merged `google/fonts` PRs.
- Do not add a `tags` field to `METADATA.pb`; recent PR checklists ask for
  new-font tags as a PR/release-review item, while the current metadata guide
  documents `category`, `stroke`, and optional `classifications` instead.
- Do not add custom `sample_text` unless Google Fonts review asks for it or the
  default Arabic specimen text is visibly inappropriate. The metadata guide
  documents `sample_text` as an override to use sparingly.

## Expected variable font metadata

```text
fonts {
  name: "Virtua Grotesk"
  style: "normal"
  weight: 400
  filename: "VirtuaGrotesk[wght].ttf"
  post_script_name: "VirtuaGrotesk-Regular"
  full_name: "Virtua Grotesk Regular"
  copyright: "Must match OFL.txt line 1 and built font name ID 0"
}
axes {
  tag: "wght"
  min_value: 400.0
  max_value: 700.0
}
```

Review notes:

- The variable filename follows the GF variable naming pattern.
- `wght` default is 400 in the font and designspace.
- Recent `google/fonts` variable metadata examples record axis min/max in
  `METADATA.pb`; the default location is reviewed from the built font's `fvar`
  table rather than by adding a `default_value` field to this preview.
- Review `documentation/google-fonts/variable-font-metadata.md` for the generated `fvar`,
  `STAT`, and `avar` state before packaging.
- Review `documentation/google-fonts/avar-readiness.md` before deciding whether to keep the
  current linear weight axis or encode a non-linear `avar` mapping.
- Review `documentation/google-fonts/google-fonts-axis-registry-audit.md` to confirm the
  built `wght` axis uses the Google Fonts axis registry display name, default,
  and fallback style labels.
- Review `documentation/google-fonts/vendor-id-readiness.md` before final packaging so the
  source UFO `openTypeOS2VendorID`, generated OS/2 `achVendID`, and
  Fontspector `googlefonts/vendor_id` warning are resolved or explicitly
  deferred together.
- If Google Fonts requests a registry default override, add it downstream during
  metadata review.

## Expected static font metadata

```text
fonts {
  name: "Virtua Grotesk"
  style: "normal"
  weight: 400
  filename: "VirtuaGrotesk-Regular.ttf"
  post_script_name: "VirtuaGrotesk-Regular"
  full_name: "Virtua Grotesk Regular"
}
fonts {
  name: "Virtua Grotesk"
  style: "normal"
  weight: 500
  filename: "VirtuaGrotesk-Medium.ttf"
  post_script_name: "VirtuaGrotesk-Medium"
  full_name: "Virtua Grotesk Medium"
}
fonts {
  name: "Virtua Grotesk"
  style: "normal"
  weight: 600
  filename: "VirtuaGrotesk-SemiBold.ttf"
  post_script_name: "VirtuaGrotesk-SemiBold"
  full_name: "Virtua Grotesk SemiBold"
}
fonts {
  name: "Virtua Grotesk"
  style: "normal"
  weight: 700
  filename: "VirtuaGrotesk-Bold.ttf"
  post_script_name: "VirtuaGrotesk-Bold"
  full_name: "Virtua Grotesk Bold"
}
```

Review notes:

- Static filenames follow the GF canonical style names, including `SemiBold`.
- The generated static Medium and SemiBold fonts currently expose typographic
  family names `Virtua Grotesk Medium` and `Virtua Grotesk SemiBold` with
  subfamily `Regular`; that is normal for non-style-linked upright statics, but
  the downstream metadata should still use `name: "Virtua Grotesk"`.
- Each static entry should carry the same copyright as `OFL.txt` and name ID 0.

## Expected subsets

Minimum after drawing:

```text
subsets: "arabic"
subsets: "latin"
subsets: "menu"
primary_script: "Arab"
```

Arabic is intended for the first Google Fonts submission. The minimum character
target is Google's `GF_Arabic_Core` glyphset, tracked in
`documentation/google-fonts/missing-gf-arabic-core.md`. Keep `primary_script: "Arab"` unless
Google Fonts review asks for a different metadata strategy for a mixed
Latin/Arabic family. Use `documentation/glyph-review/arabic-shaping-smoke-test.md` as the
local smoke-test record for Arabic GSUB behavior before downstream packaging.
Use `documentation/glyph-review/arabic-mark-readiness.md` to review Core Arabic combining
marks, dotted circle, source anchors, and `mark`/`mkmk` GPOS readiness.
Use `documentation/google-fonts/gf-glyphset-readiness.md` to review Latin/Arabic glyphset
coverage percentages and Arabic Core language codes before finalizing subsets.
Use `documentation/google-fonts/google-fonts-language-metadata.md` to confirm the local
Google Fonts language records and recent Arabic package examples support
`subsets: "arabic"` with `primary_script: "Arab"`.

## Sample text

The current recommendation is to omit `sample_text` from the first downstream
package and rely on Google Fonts' language textprotos, with
`primary_script: "Arab"` making Arabic the primary specimen-script target.
Review the default specimen after packaging. Add a custom `sample_text` block
only if Google Fonts review asks for one or if the default Arabic text is
clearly unsuitable for the design.

## Expected downstream source metadata

Recent merged new-font PRs include a `source` block that records the public
upstream repository, exact commit, source archive or branch, and
source-to-destination files. For Virtua Grotesk, review the generated package
against the selected release/archive shape:

```text
source {
  repository_url: "https://github.com/eliheuer/virtua-grotesk"
  commit: "Pending final release/source commit"
  archive_url: "https://github.com/eliheuer/virtua-grotesk/releases/download/v1.000/VirtuaGrotesk-1.000.zip"
  files {
    source_file: "OFL.txt"
    dest_file: "OFL.txt"
  }
  files {
    source_file: "fonts/variable/VirtuaGrotesk[wght].ttf"
    dest_file: "VirtuaGrotesk[wght].ttf"
  }
  files {
    source_file: "documentation/google-fonts/ARTICLE.en_us.html"
    dest_file: "article/ARTICLE.en_us.html"
  }
  files {
    source_file: "documentation/assets/readme-specimen.png"
    dest_file: "article/readme-specimen.png"
  }
  branch: "main"
}
```

Omit `source.config_yaml` for this selected release/archive path unless Google
Fonts review asks for build metadata. If the source strategy changes to
build-from-source, update this review block and
`documentation/google-fonts/google-fonts-downstream-package-preview.md` together before
running `make downstream-metadata-check`.

If Google Fonts wants only the variable font downstream, do not include the
static TTFs in `METADATA.pb`. If they request static TTFs for this family,
review the static entries above against the generated package.
If the final package uses the Article flow, confirm every Article HTML/image
asset has a source-to-destination mapping in this block.

## Article and description

The current upstream drafts are `documentation/google-fonts/ARTICLE.en_us.html` and
`documentation/google-fonts/DESCRIPTION.en_us.html`. The Google Fonts article guide says
`DESCRIPTION.en_us.html` is legacy and recent new-font PRs commonly include
`article/ARTICLE.en_us.html` plus images. Before packaging, confirm the upstream
link in the Article matches the final public repository URL.

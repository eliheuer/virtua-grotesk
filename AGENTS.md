# Agent guidance

Virtua Grotesk is an OFL variable font (wght 400 to 700) for Latin, Arabic
and Hebrew, intended for Google Fonts. The release target is every glyph
green in both masters. Eli draws and approves. Agents draft named glyphs,
build, proof, measure and report.

## State

- Progress: [STATUS.md](STATUS.md), generated by `make status` from mark colors.
  Do not take direction from older reports, worklogs or review records in the
  Git history. Take direction from Eli.
- Active inputs: `sources/VirtuaGrotesk.designspace`, the Regular and Bold
  UFOs, `sources/config.yaml`. Grid, stroke targets and mark colors:
  `sources/design.toml`.

## Work loop

The full description is in
[documentation/design/system/learning.md](documentation/design/system/learning.md).

1. `make queue` ranks the glyphs that most composites wait on. Eli names the
   glyphs to work on.
2. Draft, then run `make check-design GLYPHS="..."` and correct the findings.
   The checks are a filter. They do not measure quality.
3. Render the same text in Virtua Grotesk and the fonts in `reference-fonts/`
   at one em size and weight. Use Runebender or `make proof-web`.
4. Eli reviews and corrects. Commit the draft before the correction, so that
   the Git history holds both. The review commit changes the purple mark to
   a grade: red (broken), orange (better), yellow (close) or green.
5. When Eli asks, run `make corrections` and propose a change for each open
   correction: a rule entry, a check, a held-out case or a glyph record. The
   change cites the correction commit. Do not add worklogs, reports, receipts
   or handoff files.

## Long and unattended tasks

Task contracts are in `.agents/tasks/`: goal, acceptance, constraints and the
report. Run a contract in a separate checkout, on its own branch. After any
agent edits glyphs, run `make check-changes`. It fails when a green glyph
changed, or when the contours of a glyph changed and it is not purple.

## What belongs in the repository

The repository holds sources, tools, tests and maintained documents. It does
not hold records of work.

- Do not add worklogs, handoffs, receipts, reports, plans, audits or dated
  documents. The Git history and commit messages are the record of work.
- Generated output goes to `out/`, which Git ignores. A tracked file has at most
  500 KB, because a file stays in every clone of the history.
- Before you add a document, extend the existing one on the same subject.
  A maintained document has at most 200 lines.
- `tests/test_repository_layout.py` enforces these rules in CI. To add a new
  kind of file, change its LAYOUT list in the same commit and give the reason
  in the commit message. When you remove the last file of a kind, remove its
  pattern.
- `tests/test_documentation_references.py` fails when a document links to a
  file, path or `make` target that does not exist. When you remove a file or
  a command, update the documents that name it in the same commit.

## Source rules

- Draw or redraw only glyphs Eli names, in the masters Eli names.
- A request to clean up a glyph, or to make it "more X", is the smallest
  change to the current drawing, usually handle edits. It is not a new design.
- The reference fonts do not dictate the design. Use them to compare visual
  weight, spacing and outline consistency. If a glyph is very different from
  all of them, find out why. A small difference in form is not a defect.
- Before you show a candidate, compare the filled glyph with the reference
  fonts and the green donors. Do not show a candidate that this comparison
  shows as faulty.
- Green contour glyphs are frozen. Eli approves contour glyphs. Mark new AI
  drawing purple.
- A change to a component donor also changes every glyph that uses it. Do not
  change a donor that a green glyph uses.
- A composite that `scripts/check_design.py --ready` lists can be marked green.
- Keep contour, point and component structure compatible in both masters.
- Edit GLIF XML and plists surgically in the existing style (tabs, double
  quotes, no space before `/>`). Never call whole-UFO `font.save()`.
- Register new glyphs in `contents.plist` and `public.glyphOrder` in both masters.
- Open fonts with `runebender-serve <designspace-or-ufo> --open`.
- Files that people edit use TOML with comments. JSON is only for data that
  a program writes. `sources/config.yaml` is YAML because gftools requires it.

## Verification

Use `.venv/bin/python`. Build with `make build`, check with `make qa` and
[documentation/qa.md](documentation/qa.md), and look at the rendered output.
Command success is not visual review. Release scope and the
official Google Fonts links are in
[documentation/google-fonts.md](documentation/google-fonts.md).
Commit messages are plain, with no agent credit or trailers.

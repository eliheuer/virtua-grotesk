# Source protection and authority

A context packet supplies evidence, never authorization. The current user's
named scope and recorded unresolved decisions govern work. Historical grants
and stopped queues do not restart drawing. Reuse authorization already given
for the same scope; do not repeatedly ask for it.

Only green is frozen by default, including green composites. Inspect recursive
component donors and affected consumers: editing a non-green donor can change a
protected green drawing. A green change needs explicit glyph/master permission.
Reserved human edits also remain protected regardless of color.

Color meanings and known variants live in `contract.json`. Red permits replacement
within an authorized task. Orange/yellow preserve useful drawing. Blue/pink identify
composite work; purple identifies unreviewed AI drawing. Unknown/conflicting colors
need classification. Never assign green. New AI drawings use Eli's purple convention.

Before writing, save an exact baseline and verify the packet's source hashes.
Preserve concurrent editor saves, metrics, anchors, features and unrelated files.
Edit GLIF XML and plists surgically; never save an entire UFO with font.save().
Preserve tabs, double quotes, no space before />, and x/y/type/smooth attribute order.
Register new glyphs in both contents.plist files and public.glyphOrder.

Both masters require corresponding contour order, point counts/types and component
structure. A one-master optical edit can be scoped; structural changes must be
compatible in both. A build, applied state, human acceptance and release readiness
are distinct. Capture the user's actual feedback before revising the drawing.

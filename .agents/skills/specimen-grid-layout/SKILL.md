# /specimen-grid-layout

Layout discipline for every image and PDF this repo generates. Based on
Müller-Brockmann's modular grid ethic (*Grid Systems in Graphic Design*,
1981) and the house idiom used across eliheuer font repos (wallingford,
fg-grotesk, micro-grotesk): **the grid is the coordinate system, not
decoration.**

Image scripts are co-located under `documentation/`; the main PDF uses
`designbot proof`. Inspect the chosen script and installed CLI before editing.
The former `scripts/designbot/` directory is retired.

## The system

- **The grid helpers are inlined per script** (designbot scripts are
  single-file, so there is no shared module — inspect the current co-located scripts under `documentation/`
  before choosing a Grid implementation). Keep the
  math identical across scripts; never invent a new grid idiom per script.
- **Margin** = `min(width, height) / 16` unless a format dictates
  otherwise. **Unit** = `margin / 2`.
- **Every coordinate is a whole multiple of the unit**, measured from the
  margin lines. If you find yourself typing a raw pixel number for a
  position, snap it to the unit grid.
- **designbot matches drawbot's coordinate system: y-up, origin at the
  bottom-left**, `rect`/`oval` anchored at their bottom-left corner, and
  `Canvas::text(s, x, y)` taking the BASELINE of the first line (verify the current designbot API before changing layout code).
  Drawbot-style baseline-cursor math passes straight through to the draw
  calls — no coordinate flipping.
- **Leading in stacked text should be unit-friendly** — when rows of type
  repeat down the page, prefer leadings that put successive baselines on
  or near unit lines. Cap heights are what the eye reads; align cap-tops
  or baselines, never bounding boxes.
- **Flush left, ragged right.** Headlines and repetition blocks start at
  the left margin line. Centering is the exception (single hero glyphs),
  not the rule.
- **Restrained palette, one accent.** Near-black paper, gray-white ink,
  and the source markColor red `(255, 74, 61)` as the only accent.
  Captions live in the four corners (Font.Garden idiom), set in the font
  itself, on the margin lines. (Print proofs are the exception: black on
  white.)

## The overlay toggle

Inspect how the selected script enables its overlay. For example,
`documentation/proofs/images/weight-compare.rs` reads `GRID_VIEW`, while
`documentation/readme-images/specimen-regular.rs` has a `SHOW_GRID` constant.
Do not assume the built-in proof command or every script honors `GRID_VIEW`.

The overlay should share the layout's coordinate space: unit lines, margin
frame, and any major grid lines. Check both the overlay and final artwork.

## Optical alignment — ink, not box

A display-size headline whose text origin is on a grid line still looks
misaligned: the letterform's ink is inset by its left side-bearing. For
large type at the left margin, shift by the measured side-bearing so the
**ink** lands on the line. Side-bearings are font- and glyph-specific —
measure with the actual font being drawn (the ports parse `hmtx` for
this), never assume. Small text (captions) does not need this; apply it
from roughly 100pt up.

## Verify — render and look, don't trust the math

After any layout change:

1. Render with the selected script's grid overlay enabled.
2. Downscale for review: `sips -Z 640 out.png --out preview.png`.
3. Read the preview and check: left edges of ink on unit lines, repeated
   baselines evenly stepped, captions on the margin lines, nothing
   colliding with the caption band.
4. Render once more with the overlay off before committing — overlay
   pixels must never ship.

Inspect output size and rendering before selecting final assets. There is no
Makefile PNG-quantization step. Do not assume a script's overlay is disabled in
its committed defaults; check before exporting release artwork.

## Applying to scripts

Image scripts live alongside their outputs under `documentation/`. Inspect
an existing script before extending it. The old `scripts/designbot/` proof
and social scripts have been retired; do not use them as reference paths.
The main PDF is generated by designbot's built-in `proof` command.

For a new script, keep grid helpers consistent with the selected current
reference, render the output, and inspect both the grid overlay and final art.


## Chat design-review sheets

Eli approved DesignBot Rust scripts as the standard on 2026-10-19. Reuse
`documentation/proofs/hebrew_review.rs`, which supplies the three sheet modes;
`hebrew_review.py` is a runner/verifier, not a drawing engine. See
`documentation/qa.md#standard-designbot-comparison-workflow` for exact commands.
The old shared Python layout is historical and diagnostic only.

For this workflow Eli's explicit preferences override the marketing defaults:

- Two base grays: #dedede and #444444, swapped for light and dark versions.
  Retain both polarities. No red accents or default colored difference overlays.
- Virtua Grotesk Regular for labels. Title case for headings and short captions;
  sentence case for explanatory footnotes. Literal case-sensitive glyph tests
  retain their intended case.
- Large headlines: the v3 proposal uses 56 px and −0.02 em tracking (−1.12 px), an adjustable
  interpretation of the request for slightly tighter headlines. Other labels and
  all font samples use zero added tracking. Reset tracking after the title.
- Organize with alignment and whitespace instead of repeated slash separators.
  Put font names above review roles, weight names above numeric coordinates in
  a dedicated rail beside their samples,
  and state the rendering size once per page. Use a quiet folio and brief
  footnotes; omit redundant column numbers. This records Eli's Swiss editorial
  refinement request and subsequent layout approval on 2026-10-19.
- V3 proposal: 1600 × 1120 pages, 80 px margins and an 8 px baseline unit.
  A 128 px label rail plus a 32 px gutter places the comparison field at x=240.
  Four comparison columns: 296 px with 32 px gutters. Three columns: 384 px
  with 64 px gutters. Separate letterform, reading and weight questions.
- Eli subsequently rejected the earlier implementation's label distance and use
  of negative space (P016). This supersedes the earlier layout approval. Keep
  captions near the content they label; place weight labels alongside samples,
  and use larger intervals between meaningful groups. An overlay passing a
  coordinate check is not evidence of good typography. The precise v3 layout
  is an agent proposal awaiting review; record further corrections.

The comparison recipe's `ReviewGrid` defines both content placement and guides.
Use `--grid` for columns, gutters and row modules; `--baseline-grid` adds the
8 px baselines. With the Rust script directly use `GRID_VIEW=1` or
`GRID_VIEW=baseline`; omit it for clean output. See P017 for Eli's supplied
editorial references. Keep a clean export alongside every diagnostic overlay.
The local HEB-002 viewer switches retained DesignBot exports interactively.
Run the Python wrapper for batches: it locks the shared DesignBot cache to
prevent simultaneous invocations from mixing output paths and parameters.

In QA comparisons preserve the shared font origin, scale and baseline instead of
optically shifting each glyph's ink to the margin. This intentional exception
keeps sidebearings and proportions visible. Oversized samples fail; never hide
differences through auto-fitting. Before/after columns need separate font contexts
because their internal family names match. Use --raw; record hinting policy.

The tested renderer's transparent frames use premultiplied RGB, but image_rgba
expects straight alpha. Preserve the script's single-color alpha conversion;
otherwise dark edge halos return. Check actual ink bounds and final pixel ranges.
After layout edits, inspect all six final pages and grid overlays; verify that
headline tracking changes only the headline. Keep font/source hashes and selected
PNG evidence in the review record. Script-specific provenance belongs in HEB-001.

The initial diagnostic is `documentation/proofs/designbot_diagnostic.rs`; its
Pillow control is intentional historical evidence, not part of the new standard
sheets. It isolated Helvetica hinting behavior before Eli selected Virtua labels.

For the current-only he/het/tav review, use `--group he-het-tav` in the runner.
It uses three columns and a common 160 px/em form size; never invent a candidate
column before a candidate exists. The later long mixed Latin–Hebrew specimen
follows the alphabet pass and will be designed with Eli; see design-review/README.md.


## Live browser review (P018)

Eli subsequently chose live font rendering for interactive proofing. Use the
browser-review section of documentation/qa.md. The Rust page dimensions above
remain specific to fixed DesignBot exports. Do not reproduce a 1600 px canvas
and CSS-scale it into a narrow browser panel. Use responsive columns, readable
metadata, actual font files at the selected CSS em size and explicit overflow.
Keep sample scales equal and grid guides tied to the actual content structure.
Native browser metrics apply; distinguish this renderer from historical images.
